# FreeModbus

## 1. Modbus协议概述

​		**Modbus**是一种工业级主从式串行通信协议，由Modicon公司（现施耐德电气）于1979年为可编程逻辑控制器PLC通信设计。作为工业自动化领域事实上的通信标准，其采用"**请求-响应**"机制，支持多种物理层接口和传输模式。已成为工业控制系统的行业标准之一

### 1.1 modbus

- **层次**：**Modbus**是一种应用层协议，它定义了客户端和服务器之间的通信规则，包括如何打包请求和响应消息。这意味着Modbus不仅定义了数据的格式，还定义了设备间交互的方式。
- **功能**：**Modbus**允许设备之间读取或写入寄存器值，执行命令，或者查询状态信息等。它**提供了具体的命令集**和数据结构，使得不同制造商的设备能够相互理解和交流。
- **Modbus**则是关于设备间如何使用这些比特来传递有意义的信息的协议。

| 寄存器类型       | 英文名           | 可读/可写 | 描述                                                                 |
|------------------|------------------|-----------|:---------------------------------------------------------------------|
| 线圈（Coils）    | Coils            | 读/写     | 用于表示开关量输出（数字量输出），例如继电器的通断状态、设备指示灯的亮灭控制等。 |
| 离散输入（Discrete Inputs） | Discrete Inputs | 只读      | 用于表示开关量输入（数字量输入），例如传感器的检测状态（如红外传感器是否检测到物体）、按钮的按下/弹起状态等。 |
| 输入寄存器（Input Registers） | Input Registers | 只读      | 用于存储模拟量输入数据，例如温度传感器采集的环境温度值、电压传感器检测的电路电压值、电流传感器测量的电流数据等连续变化的物理量。 |
| 保持寄存器（Holding Registers） | Holding Registers | 读/写 | 可用于存储模拟量输出数据或设备配置参数，常用于设置设备运行参数（如电机转速目标值）、设备地址等，且数据可长期保持，断电后一般不会丢失（具体取决于设备设计）。 |

### 1.2 RS-485

- **定义**：一种差分信号传输的串行通信标准，支持多点通信。
- **电气特性**：

- - 差分信号（A/B 线）
  - 抗干扰能力强，适合长距离通信

- **通信方式**：半双工或全双工（取决于硬件设计）
- **最大距离**：可达 1200 米
- **拓扑结构**：多点总线型（最多支持 32~256 个节点）
- **常见用途**：工业自动化、楼宇控制、传感器网络等
- **典型接口**：接线端子
- **RS-485** 主要用来传输 UART 协议的数据，只是在物理层做了差分处理，提高了稳定性和传输距离。

**Modbus RTU**

1. 1. 采用二进制编码，传输效率最高，其帧结构为：
       [Address(1B)](设备地址) + [Function(1B)](功能码)  + [Data(N B)](数据) + [CRC(2B)](CRC校验) 
   2. 技术特点：

- - 采用3.5字符静默时间作为帧间隔
  - CRC-16校验多项式：0x8005
  - 波特率自适应（1200-115200bps）

# 2. Modbus RTU

## 2.1 主从发送

**Modbus RTU**通信基于主从架构，主站（Master）发送**请求帧**，从站（Slave）返回**响应帧**。

帧格式如下：

**设备地址（1字节） + 功能码（1字节） + 数据（N字节） + CRC校验（2字节）**

- 其中设备地址用于多个从设备识别，具体方法需要从设备接收数据帧时判断。
- 功能码代表不同的命令。
- 数据表示写入的内容，不同的功能码写入的内容不同。
- CRC校验用于收发消息确认是否有效。

## 2.3 **如何计算 3.5 字符时间？**

静默时间取决于 **波特率（Baud Rate）** 和 **数据格式**（如 8N1，即 8 数据位、无校验、1 停止位）：

- **1 个字符时间** = (1 起始位 + 8 数据位 + 1 停止位) / 波特率
  （例如，19200bps 时，1 字符时间 ≈ 10 bits / 19200 = 520.8μs）
- **3.5 字符时间** = 3.5 × 1 字符时间
  （**19200**bps 时，3.5 字符时间 ≈ **1.82ms**）

每个“**字符时间**”取决于通信的波特率。

例如，在**9600**波特率下，一个比特时间为1/9600秒，考虑到标准的8个数据位、1个起始位、1个停止位和无校验位（共11位）的情况，一个字符的时间大约是1.146毫秒。所以，3.5个字符时间大约是**4毫秒**。
