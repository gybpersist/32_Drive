# MQTT 指南


## 一、什么是 MQTT（以太网、NB-IoT 场景适用）
MQTT（Message Queuing Telemetry Transport，消息队列遥测传输协议）是一种**轻量级、基于发布/订阅（Publish/Subscribe）模式**的应用层消息传输协议，专门为资源受限设备（如嵌入式设备）、低带宽、高延迟或不稳定的网络环境（如以太网、NB-IoT、LoRa 等）设计，广泛应用于物联网（IoT）领域。


### 1.1 MQTT 核心特性
- **轻量级与高效**：消息头最小仅 2 字节，协议开销极低，适合硬件资源有限的嵌入式设备（如 MCU）和带宽紧张的场景（如 NB-IoT）。
- **发布/订阅模式**：
  - 发布者（Publisher）：向指定“主题（Topic）”发送消息，无需知道订阅者的存在。
  - 订阅者（Subscriber）：订阅感兴趣的“主题”，仅接收该主题的消息，无需知道发布者的存在。
  - 代理（Broker）：中间转发节点，负责接收发布者的消息并转发给对应订阅者（如 Mosquitto 就是一款 MQTT Broker）。
- **三级消息可靠性（QoS）**：
  - **QoS 0（最多一次）**：消息仅发送一次，不确认、不重传，适合非关键数据（如实时温度采集）。
  - **QoS 1（至少一次）**：消息至少送达一次，接收方需发送确认（ACK），发送方未收到 ACK 则重传，适合确保数据不丢失（如设备控制指令）。
  - **QoS 2（仅一次）**：通过“四步握手”确保消息仅送达一次，无重复，适合严格要求无冗余的场景（如计费数据）。
- **Keep Alive 心跳机制**：客户端与 Broker 约定心跳间隔（如 60s），客户端定期发送“PINGREQ”包，Broker 回复“PINGRESP”包，确保连接存活；若超时无响应，双方判定连接断开。
- **持久化会话**：客户端可配置“Clean Session = 0”，Broker 会保存客户端的订阅列表和未完成的 QoS 1/2 消息；客户端重新连接后，Broker 会补发未接收的消息，适合断电恢复等场景。


### 1.2 MQTT 与 TCP 的关系
MQTT 依赖 TCP 协议提供底层支撑，二者在 TCP/IP 模型中的定位不同：
| 协议层级 | 协议名称 | 核心作用 | 关系 |
|----------|----------|----------|------|
| 传输层   | TCP      | 提供**面向连接、可靠、有序**的字节流传输服务（通过三次握手建立连接、重传机制、确认机制保障可靠性） | MQTT 运行在 TCP 之上，依赖 TCP 解决“数据是否能可靠到达”的问题 |
| 应用层   | MQTT     | 定义**消息格式、发布/订阅逻辑、QoS 机制**，解决“设备间如何高效传递消息”的问题 | 基于 TCP 提供的可靠通道，实现设备间的消息交互 |


## 二、MQTT 实践：环境搭建（Windows 系统）
### 2.1 步骤 1：下载并安装 Mosquitto（MQTT Broker）
Mosquitto 是一款轻量级、开源的 MQTT 代理（Broker），支持 Windows、Linux 等系统，适合本地调试和小型部署。

1. **下载地址**：[Eclipse Mosquitto 官网](https://mosquitto.org/download/)，选择 Windows 版本（如 `mosquitto-2.0.18-install-windows-x64.exe`）。
2. **安装建议**：
   - 选择默认安装路径（如 `C:\Program Files\mosquitto`），便于后续配置和启动。
   - 安装时勾选“Add Mosquitto to PATH”（可选，方便命令行直接调用）。


### 2.2 步骤 2：修改 Mosquitto 配置（允许远程连接）
Mosquitto 默认配置仅允许本地（127.0.0.1）连接，若需其他设备（如开发板、手机）连接，需修改配置文件：

1. **找到配置文件**：进入安装路径 `C:\Program Files\mosquitto`，找到 `mosquitto.conf`（注意：修改需管理员权限，建议右键用“记事本/Notepad++”以管理员身份打开）。
2. **添加配置项**：在文件末尾添加以下两行，允许所有 IP 连接并禁用匿名认证（可选，根据需求调整）：
   ```ini
   # 允许所有IP地址连接（默认仅本地）
   allow_anonymous true
   # 监听端口（默认 1883，MQTT 标准端口）
   listener 1883 0.0.0.0
   ```
   - `allow_anonymous true`：允许匿名连接（调试阶段推荐，生产环境建议开启账号密码认证）。
   - `listener 1883 0.0.0.0`：监听 1883 端口，`0.0.0.0` 表示允许所有网卡的 IP 访问。


### 2.3 步骤 3：启动 Mosquitto Broker
1. **打开命令行工具**：按下 `Win + R`，输入 `powershell` 打开 PowerShell（或用“管理员身份”打开，避免权限问题）。
2. **切换到 Mosquitto 安装目录**：
   ```powershell
   cd "C:\Program Files\mosquitto"
   ```
3. **启动 Broker 并加载配置文件**：
   ```powershell
   mosquitto -v -c .\mosquitto.conf
   ```
   - 参数说明：
     - `-v`：启用 verbose 模式，打印详细日志（便于调试）。
     - `-c .\mosquitto.conf`：指定加载的配置文件路径。

4. **常见问题：端口被占用**
   - 若启动时提示“Address already in use”（地址已被占用），说明 1883 端口被其他程序占用（可能是 Mosquitto 服务默认启动）。
   - 解决方法：
     1. 打开“任务管理器”→“服务”标签页，找到“Mosquitto”服务。
     2. 右键“停止”该服务，再重新执行启动命令。

### 2.5 步骤 5：使用 MQTTX 测试“发布/订阅”
#### 5.1 第一步：创建 MQTT 连接（连接到本地 Mosquitto Broker）
1. 打开 MQTTX，点击左上角“+”号，新建连接，配置如下参数：
   - **连接名称**：自定义（如“本地 Mosquitto 连接”）。
   - **服务器地址（Broker）**：`tcp://127.0.0.1:1883`（本地 Broker 地址，若连接其他设备，替换为对应 IP，如 `tcp://192.168.1.100:1883`）。
   - **端口**：1883（与 Mosquitto 配置的监听端口一致）。
   - **其他参数**：默认（Clean Session 勾选、Keep Alive 60s、无账号密码）。
2. 点击“连接”，若连接成功，左侧连接名称会显示“在线”状态。


#### 5.2 第二步：订阅主题（模拟“订阅者”）
1. 在 MQTTX 连接成功的界面中，点击下方“订阅”按钮。
2. **主题（Topic）**：输入自定义主题（如 `sensor/temperature`，主题支持多级分层，用 `/` 分隔）。
3. **QoS**：选择 QoS 0（调试阶段推荐）。
4. 点击“确认”，即可完成主题订阅，后续将接收该主题的所有消息。


#### 5.3 第三步：发布消息（模拟“发布者”）
1. 在 MQTTX 界面中，点击下方“发布”按钮。
2. **主题（Topic）**：输入与订阅一致的主题（如 `sensor/temperature`，必须完全匹配才能被订阅者接收）。
3. **QoS**：选择 QoS 0（与订阅端一致）。
4. **消息内容**：输入要发送的消息（支持文本、JSON 等格式，如 `{"temperature": 25.5, "humidity": 60}`）。
5. 点击“发送”，订阅端会立即收到该消息，并在界面中显示。


## 三、总结
- **MQTT 定位**：轻量级应用层协议，适合 IoT 设备在低带宽、不稳定网络中通信，核心是“发布/订阅”模式和三级 QoS 可靠性。
- **环境搭建核心**：
  1. Mosquitto 作为 Broker，负责消息转发，需配置允许远程连接。
  2. MQTTX 作为客户端，快速测试“发布/订阅”流程，验证 Broker 是否正常工作。
- **后续扩展**：可将嵌入式设备（如 STM32 + W5500/NB-IoT 模块）作为 MQTT 客户端，接入 Mosquitto Broker，实现设备与云端/本地的消息交互。
